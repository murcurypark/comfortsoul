# comfortsoul

지수와 성수의 결혼준비 대시보드 (`index.html`, 브라우저에서 바로 열기 / GitHub Pages)

## 화면 구성

태블릿을 기준으로 만들었고 폰에서도 같은 기능을 씁니다. 모든 화면에서 본문 글자는 14px 이상, 누르는 칸은 44px 이상입니다.

| 화면 | 탭 위치 | 배치 |
|---|---|---|
| 폰 (~599px) | 아래 탭 바 | 한 열 |
| 태블릿 세로 (600~899px) | 위쪽 탭 | 한 열, 요약 타일 4칸 |
| 태블릿 가로·큰 화면 (900px~) | 왼쪽 사이드바 | 종합은 2열(1500px~는 3열), 할 일은 체크리스트 + 지금 챙길 일 |

- **종합**: 요약, 지금 챙길 일, 체크리스트, 예산, 하객, 업체를 한 화면에서 보고 바로 고칠 수 있습니다.
- **할 일 / 예산 / 하객·업체 / 시세**: 한 가지씩 크게 보고 고칩니다. 종합과 탭은 같은 데이터를 고치므로 어디서 고쳐도 같이 바뀝니다.
- 글자를 누르면 고칠 수 있고, 삭제하면 "되돌리기"가 나옵니다. 열려 있는 탭은 주소(`#budget` 등)에 남습니다.

## 로그인과 저장소 (Firebase)

로그인 전에는 쓰는 기기의 브라우저에만 저장됩니다. **구글 계정으로 로그인**하면 그 계정 전용 **내 저장소**(Firestore, 무료 요금제)에 저장되고, 다른 사람은 볼 수 없습니다.
**커플은 "커플 코드"로 같은 저장소를 함께 씁니다.** 한 분이 커플 저장소를 만들면 코드가 나오고, 상대방이 로그인한 뒤 그 코드를 입력하면 같은 저장소로 들어옵니다.
한 분이 고치면 상대방 화면에 바로 나타납니다. 누가 가입하든 계정별로 저장소가 따로 생기므로 허용할 이메일을 규칙에 적을 필요가 없습니다.

**사용하는 사람**
1. 사이트에서 **Google로 로그인**합니다. 처음에는 내 저장소를 씁니다(지금 입력한 내용이 그대로 올라갑니다).
2. 커플이라면 한 분이 설정 창(위쪽 상태 버튼)에서 **커플 저장소 만들기**를 누르고, 나온 코드를 상대방에게 보냅니다. 지금까지 쓴 내용이 커플 저장소에 올라갑니다.
3. 상대방은 로그인한 뒤 같은 설정 창의 **커플 코드** 칸에 코드를 넣고 **참여**합니다. 아직 손대지 않은 예시 데이터만 있으면 묻지 않고 저장된 내용이 보이고, 직접 입력한 내용이 있으면 "저장된 내용 불러오기 / 내 내용으로 덮어쓰기" 중에서 고르게 합니다.
4. **내 저장소로 돌아가기**를 누르면 혼자 쓰던 내용으로 돌아갑니다. 커플 저장소의 내용은 그대로 남고, 코드를 다시 넣으면 돌아올 수 있습니다.

**관리하는 사람 (한 번만)**
1. Firebase 콘솔 → **빌드 → Authentication → 시작하기 → 로그인 방법(Sign-in method) → Google**을 **사용 설정**하고 프로젝트 지원 이메일을 고릅니다.
2. 대시보드 설정 창의 **"처음 설정하는 사람"**에 있는 규칙을 복사해 콘솔 **Firestore Database → 규칙**에 붙여 넣고 **게시**합니다. (Firestore 데이터베이스는 프로덕션 모드로 미리 만들어 둡니다.)

```
match /users/{uid} { allow read, write: if request.auth != null && request.auth.uid == uid; }
match /spaces/{space}/{coll}/{id} {
  allow read, write: if request.auth != null && (space == request.auth.uid || space.matches('c_[A-Z2-7]{24}'));
}
```

- 데이터는 `spaces/{uid}/…`(내 저장소)와 `spaces/c_{코드}/…`(커플 저장소)에 저장됩니다. 계정별로 어느 저장소를 쓰는지는 `users/{uid}`에 있어서, 다른 기기에서 로그인해도 같은 저장소로 이어집니다.
- **다른 사람의 개인 저장소는 열 수 없습니다.** 커플 저장소는 **코드를 아는 로그인한 사람**이 읽고 쓸 수 있으므로, 코드(24자 무작위)는 두 분께만 알려 주세요.
- 항목마다 따로 저장되어서, 두 사람이 서로 다른 항목(또는 같은 항목의 다른 칸)을 동시에 고쳐도 둘 다 남습니다. 인터넷이 끊겨도 입력할 수 있고, 연결되면 자동으로 저장됩니다.
- `index.html` **파일로 직접 열면 로그인할 수 없습니다.** 웹 주소(배포한 주소)로 여세요.
- 승인된 도메인: `*.web.app`, `*.firebaseapp.com`, `localhost`는 기본으로 허용됩니다. 다른 주소(예: `github.io`)는 콘솔 → Authentication → 설정 → 승인된 도메인에 추가해야 로그인됩니다.
- Firebase 웹 설정값(`firebase-default`)은 공개되어도 되는 값이라 코드에 들어 있습니다. 다른 Firebase 프로젝트를 쓰려면 이 값을 바꾸세요.

### 테스트

실제 Firebase SDK와 Auth·Firestore 에뮬레이터, 위 보안 규칙으로 검증했습니다(계정별 저장소 분리, 커플 저장소 생성·참여·나가기, 다른 기기 로그인, 남의 저장소 접근 차단, 오프라인). 에뮬레이터는 Java가 필요합니다.

## 배포 (Firebase Hosting)

`firebase.json`과 `.firebaserc`가 들어 있어서 같은 Firebase 프로젝트(`jisu-seongsu-wedding`)에 바로 올릴 수 있습니다. 올라가는 파일은 `index.html` 하나입니다.
주소는 `https://jisu-seongsu-wedding.web.app` 입니다. 레포가 비공개여도 상관없고, 무료 요금제 안에서 충분합니다. 이 주소에서 로그인이 바로 동작합니다.

1. Firebase 콘솔 → **빌드 → Hosting → 시작하기**를 한 번 눌러 둡니다 (안내 화면은 끝까지 눌러 넘기면 됩니다).
2. 내 컴퓨터에서 (Node.js 필요) 레포 폴더로 들어가 아래를 실행합니다.
   ```
   npm install -g firebase-tools
   firebase login
   firebase deploy --only hosting
   ```
3. 앞으로 고칠 때마다 `firebase deploy --only hosting`만 다시 실행하면 됩니다.

푸시할 때마다 자동으로 올리려면 레포 폴더에서 `firebase init hosting:github`을 한 번 실행하세요. GitHub 연결과 배포용 비밀값 등록, 워크플로 파일 생성을 안내에 따라 해 줍니다. 비공개 레포에서도 동작합니다.

- 배포된 페이지는 주소를 아는 누구나 열 수 있지만, **데이터는 로그인과 보안 규칙(위)이 지킵니다.** 페이지에는 개인 정보가 들어 있지 않습니다.
- 선택: Google Cloud 콘솔 → API 및 서비스 → 사용자 인증 정보에서 이 프로젝트의 브라우저 키에 **HTTP 리퍼러 제한**으로 `jisu-seongsu-wedding.web.app/*`를 걸면, 다른 사이트에서 이 키를 쓰는 것을 막을 수 있습니다. (파일로 열어 쓰는 경우에는 걸지 마세요.)
- GitHub Pages는 무료 플랜에서 비공개 레포로는 쓸 수 없으므로, 레포를 비공개로 바꾸면 Pages 주소는 닫힙니다.

## 시세 데이터 갱신

예산 옆의 참고 시세와 "시세 참고" 카드는 `wedding_data` SQLite DB에서 뽑은 집계값입니다.
DB가 바뀌면 아래 명령으로 `index.html` 안의 데이터를 다시 넣습니다.

```
python3 tools/build_market.py path/to/wedding_data_clean.db
```

DB 원본(업체 연락처, 후기 작성자 등)은 레포에 올리지 않고 집계값과 출처만 페이지에 들어갑니다.
